\section{Prospective architecture and horizon replication}

The follow-up uses new independent training pools and new validation/ID/OOD reference sets (32/128/64 inputs), preserving the gain-two channel family, 512-interval fine solve and 129-by-129 observation grid. All inputs use the same 129-grid log-coefficient sensors. The second architecture is the archived convolutional-branch DeepONet with rank 32; this is not a parameter-count-matched architecture ranking. Both architectures receive three 60-second learning-rate trials per method, using validation only. The FNO grid is 0.002/0.008/0.032; the DeepONet grid is 0.0005/0.002/0.008, chosen from its historical search range before the new results. This is equal allocated search time, not exhaustive architecture optimization.

Five new data-pool/optimization seeds are paired across methods and architectures. DeepONet runs five methods to 180 seconds, with a 120-second checkpoint. FNO runs four methods from scratch to 600 seconds, with 120/180/360-second checkpoints. It does not resume archived best-model checkpoints without optimizer state. Learning rates retain the common wall-time decay, with no retuning at long endpoints. Thus this is a fixed-policy horizon test, not a claim of converged performance. Shared reference construction and offline testing are separately recorded; labels, initialization, training inputs, validation and checkpoints remain inside each run timer.

These results remain limited to one PDE family. They test transfer to one additional architecture and a longer finite construction horizon, not cross-PDE universality, complete convergence, or numerical-solver optimality. No test-driven parameter reselection, seed deletion or failed-run replacement is performed.
